# Contribuir para o projeto

O desenvolvimento requer Node.js 20 ou posterior. Instale as dependências com `npm ci` e execute `npm test` e `npm run smoke`. O código está dividido por responsabilidade: perfis e fluxos em `src/capabilities.ts`, competências em `src/skills.ts`, papéis em `src/roles.ts`, textos instalados em `src/docs.ts`, ficheiros nativos de cada CLI em `src/generators.ts` (reunidos em `src/catalog.ts`) e o instalador em `src/installer.ts`. O directório `dist/` compilado é versionado para permitir a instalação directa a partir do Git sem ferramentas de compilação no computador de destino. Quando alterar `src/`, execute `npm run build` e inclua os artefactos actualizados de `dist/`; o CI recompila e testa esses artefactos. Acrescente testes para cada novo destino e para alterações à gestão de propriedade dos ficheiros, aos conflitos ou à desinstalação. Não inclua estado real, tokens, chaves ou caminhos privados nos modelos.

`npm test` executa sobre a pasta `dist/` local e **não** detecta erros de empacotamento: a ausência de um módulo na propriedade `files` do `package.json` só é revelada depois de publicar. Execute `npm run smoke` antes de abrir um pedido de integração; este comando empacota o projeto, instala o arquivo comprimido num projeto limpo e valida a instalação nos quatro CLIs. A integração contínua executa ambos os comandos em Linux, Windows e macOS, com Node.js 20 e 22.

**CI local.** Quando a CI remota não está disponível (por exemplo, conta GitHub sem quota de Actions ou com o pagamento em atraso), `npm run ci` repete os passos de `.github/workflows/ci.yml`: instalação limpa, testes, `npm audit`, verificação de que `dist/` está sincronizado, smoke e testes em Node 20 e 22 (através de `npx`, sem instalar nada globalmente). Opções: `npm run ci -- --skip-install` (não apaga `node_modules`) e `npm run ci -- --node 22` (ou `none`). Não cobre o Windows. Sem CI remota, a release faz-se à mão: construir a partir da tag numa cópia limpa (`git worktree add`), repetir os passos do workflow de release, `npm pack` e `gh release create vX.Y.Z <tarball> --generate-notes --verify-tag`; usar caminhos absolutos ao instalar o tarball, porque `pasta/ficheiro.tgz` é lido pelo npm como um repositório GitHub.

Se alterar o texto de `instruction()` em `src/catalog.ts`, acrescente o texto anterior exacto à lista devolvida por `superseded()` em `src/blocks.ts`. Caso contrário, as instalações existentes deixarão de poder ser actualizadas e apresentarão o erro `Bloco de instruções alterado`.
