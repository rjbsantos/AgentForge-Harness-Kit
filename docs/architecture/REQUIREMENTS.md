# Requisitos do AgentForge Harness Kit

Cada requisito tem um identificador estável, uma prioridade (MoSCoW) e os testes que o verificam, no formato `ficheiro::título`. `src/tests/requirements.test.ts` falha se um requisito Must não tiver teste, se o ficheiro não existir ou se o título já não constar dele. Acrescentar uma capacidade obriga, portanto, a acrescentar o requisito e o teste.

| ID | Requisito | Prioridade | Testes |
| --- | --- | --- | --- |
| KREQ-001 | A instalação é idempotente, preserva instruções e ficheiros do utilizador e nunca sobrescreve nem apaga ficheiros editados. | Must | `installer.test.ts::installs all CLI surfaces, keeps user instructions and supports idempotence`; `installer.test.ts::edited generated files are never overwritten or deleted` |
| KREQ-002 | Uma instalação falhada repõe todos os ficheiros e permite repetir; um temporário obsoleto não a bloqueia. | Must | `installer.test.ts::failed install rolls back every file and allows a clean retry`; `security.test.ts::um temporário obsoleto do manifesto não bloqueia a instalação` |
| KREQ-003 | Nenhuma escrita ou leitura gerida atravessa uma ligação simbólica nem sai da raiz do projecto. | Must | `installer.test.ts::blocks generated paths through symlinks`; `security.test.ts::model-profiles.json não é lido através de um symlink` |
| KREQ-004 | Lições exigem evidência, começam pendentes e só as aprovadas entram no contexto, dentro do orçamento. | Must | `memory.test.ts::lessons require evidence and review; only approved relevant lessons enter brief context`; `memory.test.ts::context retrieval stays within an estimated token budget and reports omitted lessons` |
| KREQ-005 | Aprovar lições e refazer o selo exige uma pessoa num terminal; um agente com stdin redireccionado é recusado. | Must | `memory.test.ts::CLI supports lesson capture and concise retrieval; approval needs a terminal` |
| KREQ-006 | O selo das lições não pode ser forjado sem a chave guardada fora do projecto; edições fora do CLI deixam as lições de fora. | Must | `memory.test.ts::a seal recomputed without the key is rejected; old unkeyed seals must be re-reviewed`; `memory.test.ts::lessons edited outside the CLI are not reused until resealed` |
| KREQ-007 | As alterações a lições ficam num registo de auditoria com cadeia de hashes, sem o texto das lições. | Should | `memory.test.ts::lesson changes are written to a hash-chained audit log` |
| KREQ-008 | Os papéis só de leitura negam a escrita no formato nativo de cada CLI e o OpenCode recusa flags do git que escrevem. | Must | `contracts.test.ts::papéis só de leitura negam a escrita no formato nativo de cada CLI`; `security.test.ts::papéis só de leitura do OpenCode recusam flags do git que escrevem ou executam programas` |
| KREQ-009 | Os ficheiros gerados não contêm segredos e os agentes de segurança têm limites explícitos. | Must | `security.test.ts::os ficheiros gerados para todos os CLIs não contêm segredos`; `security.test.ts::os agentes de segurança têm limites explícitos: só o projecto, sem produção nem alvos de terceiros` |
| KREQ-010 | O endurecimento opcional acrescenta e remove só as suas regras de recusa de leitura de segredos. | Should | `security.test.ts::harden acrescenta e remove só as regras do AgentForge, preservando as do utilizador` |
| KREQ-011 | O encaminhamento recusa em vez de adivinhar e escala por risco mesmo com plano aprovado. | Must | `intent.test.ts::encaminhamento: pedidos sem fluxo são recusados em vez de adivinhados`; `routing.test.ts::approved low-risk tasks use economy; missing plan or approval escalates`; `routing.test.ts::labelled corpus keeps the classifier stable` |
| KREQ-012 | Uma proposta (`plan`) nunca afirma execução; só são registadas execuções declaradas e validadas. | Must | `orchestrator.test.ts::only explicit verified run events are logged; proposals do not claim execution`; `operations.test.ts::insights reject malformed operation history with the offending line` |
| KREQ-013 | Um resultado `passed` pode ter evidência verificável; alteração ou perda da evidência é visível nos indicadores. | Should | `operations.test.ts::a evidência registada é verificada: alterada ou em falta deixa de contar como verificada` |
| KREQ-014 | `agentforge trace` valida que cada requisito Must tem critério, aprovação, plano e teste. | Should | `trace.test.ts::trace: requisitos Must sem critério, aprovação, plano ou teste e referências órfãs são reportados`; `trace.test.ts::trace: um projecto com requisitos, plano e testes coerentes não tem lacunas` |
| KREQ-015 | O servidor MCP é só de leitura. | Must | `mcp.test.ts::MCP server lists read-only tools and answers plan, route and context calls` |
| KREQ-016 | O arranque de cada sessão cabe no orçamento de tokens declarado. | Should | `contracts.test.ts::orçamento de arranque: só o essencial é lido em cada sessão e cabe em 1500 tokens estimados` |
| KREQ-017 | A documentação referida existe e a versão é coerente entre README e CHANGELOG. | Should | `docs.test.ts::a versão do pacote é a mesma no README, no README em inglês e no CHANGELOG`; `docs.test.ts::as ligações relativas da documentação apontam para ficheiros existentes` |
| KREQ-018 | O componente de terceiros embebido é o que está declarado em `THIRD_PARTY_NOTICES.md`. | Should | `supply-chain.test.ts::a competência de terceiros embebida coincide com o resumo declarado` |
| KREQ-019 | A CI fixa as acções por SHA, declara permissões mínimas e a release publica checksum e proveniência. | Should | `supply-chain.test.ts::os fluxos de CI fixam acções por SHA e declaram permissões mínimas` |
| KREQ-020 | Só o comando de hook exacto do kit é reconhecido; uma alteração é detectada pelo `doctor` e bloqueia a reinstalação. O stdin do hook e os registos têm limites. | Should | `robustness.test.ts::hook: só o comando exacto conta; um comando alterado é detectado e bloqueia a reinstalação`; `robustness.test.ts::hook-event limita o stdin e roda o registo ao exceder o limite`; `robustness.test.ts::operations.jsonl é arquivado ao exceder o limite e os indicadores agregam os arquivos` |
| KREQ-021 | O servidor MCP limita o tamanho das mensagens e os orçamentos, e só aceita `approved` apoiado num checkpoint APROVADO. | Must | `robustness.test.ts::MCP: mensagem acima do limite é recusada e o servidor continua; budgetTokens é limitado`; `robustness.test.ts::MCP: `approved` só vale com um checkpoint cujo veredicto é APROVADO` |
| KREQ-022 | Pedidos destrutivos ou sobre segredos, em vários idiomas, escalam mesmo com plano aprovado. | Must | `routing.test.ts::pedidos destrutivos ou sobre segredos em vários idiomas escalam mesmo com plano aprovado` |
| KREQ-023 | O OpenCode recusa a leitura de segredos por omissão e `harden` respeita o `opencode.json` do utilizador. | Should | `security.test.ts::OpenCode: o opencode.json gerado recusa segredos e o harden respeita o opencode.json do utilizador` |
| KREQ-024 | Um `passed` registado pelo CLI exige evidência ou a declaração explícita de que não existe. | Should | `cli.test.ts::record, insights and lessons round-trip through the CLI` |
| KREQ-025 | O `doctor` assinala um `agentforge` resolvido dentro do projecto. | Should | `robustness.test.ts::hook: o doctor assinala um agentforge resolvido dentro do projecto; o evento aceita `tool`` |
| KREQ-026 | O fluxo `release-closure` cobre as 14 áreas da checklist de fecho de versão e só publica com autorização expressa. | Should | `release.test.ts::release-closure: percorre as 14 áreas da checklist e só publica com autorização expressa`; `release.test.ts::release-closure: o modelo contém as 14 áreas, o critério de publicação e o relatório final`; `release.test.ts::forge-release e forge-e2e fixam as regras de versão, publicação e instabilidade` |
| KREQ-027 | Um pedido vago é recusado com no máximo quatro perguntas e uma recomendação cada, antes de gastar um fluxo; `plan` devolve `needs-context`. | Must | `flow-gate.test.ts::gate: pedidos vagos são recusados com as perguntas que faltam; pedidos concretos passam`; `flow-gate.test.ts::gate: plan devolve needs-context com as perguntas, sem gastar o fluxo` |
| KREQ-028 | Os fluxos declaram os sub-fluxos que chamam; as referências existem e não há ciclos. | Must | `flow-gate.test.ts::composição: sub-fluxos existem, não formam ciclos e cada passo está dentro do fluxo` |
| KREQ-029 | Um fluxo corre completo e por ordem: passos com evidência ou nota, decisões humanas só em terminal, fecho recusado com pendentes. | Must | `flow-gate.test.ts::flow: não deixa dar passos fora de ordem, exige evidência e recusa fechar incompleto`; `flow-gate.test.ts::flow: passos paralelos podem avançar por qualquer ordem e abandonar liberta o fluxo`; `flow-gate.test.ts::flow: no CLI, os passos de decisão humana são recusados com stdin redireccionado` |
| KREQ-030 | Ficheiros que o kit deixou de gerar são removidos numa actualização (se não foram alterados) e o manifesto antigo continua válido. | Must | `installer.test.ts::actualizar um projecto que tem ficheiros entretanto retirados do kit remove-os e limpa o manifesto` |
| KREQ-031 | O kit cobre o tratamento de relatórios SAST, a modernização para o Edge, guardrails e red team. | Should | `flow-gate.test.ts::novos fluxos: SAST, Edge, guardrails e red team estão completos, encaminhados e compostos` |
| KREQ-032 | O kit cobre as funções de gestor de projecto: plano e marcos, controlo de alterações, comunicação e orçamento, com os valores sempre apoiados em fonte. | Should | `pm-flows.test.ts::fluxos de gestão: plano, alterações, comunicação e orçamento estão completos, encaminhados e compostos` |
| KREQ-033 | Um guarda opcional bloqueia commit em main, push forçado ou para main e publicação sem autorização humana com prazo, concedida só em terminal. | Should | `guard.test.ts::guarda: bloqueia commit e push para main, push forçado e publicação; deixa passar o trabalho normal`; `guard.test.ts::guarda: uma autorização humana com prazo liberta só o seu âmbito e expira`; `guard.test.ts::guarda: o comando `guard check` bloqueia com código 2 no ramo main e deixa passar noutro` |
| KREQ-034 | A eficácia mede-se com tarefas do utilizador, com e sem o kit, com limite de execuções e avisos de ruído. | Should | `eval.test.ts::avaliação: distingue o braço com kit do braço sem kit e passa o pedido por ambiente`; `eval.test.ts::avaliação: recusa gastar tokens acima do limite, valida a suite e respeita o tempo máximo` |
| KREQ-035 | Os indicadores de uso mostram se o processo é seguido: fluxos fechados, passos dispensados, evidência, porta de entrada e guarda. | Should | `eval.test.ts::indicadores de uso: fluxos fechados, passos dispensados, evidência, porta de entrada e guarda` |
| KREQ-036 | O `agentforge` avisa, sem atrasar nem falhar, quando há uma versão mais recente; só consulta a rede num terminal, com cache e recuo, e pode ser desactivado. | Should | `update.test.ts::actualização: consulta quando há rede permitida, guarda em cache e avisa só se estiver desactualizada`; `update.test.ts::actualização: uma falha de rede é silenciosa e não repete a consulta de imediato; pode ser desactivada`; `update.test.ts::actualização: o CLI avisa no stderr a partir da cache, sem alterar o stdout nem os hooks` |
| KREQ-037 | A porta de entrada devolve decisões tipadas e aceita um decisor externo que só a torna mais exigente e falha para a heurística. | Should | `decider.test.ts::decisões tipadas: pronto (sim/não), especificidade (pontuação) e fluxo (escolha com candidatos)`; `decider.test.ts::decisor externo: só torna a porta mais exigente e nunca relaxa a heurística`; `decider.test.ts::decisor externo: escolhe o fluxo quando a heurística não identifica nenhum e falhas voltam à heurística` |
| KREQ-038 | A suite de avaliação do repositório é válida e a sua linha de base não passa por acaso. | Should | `eval.test.ts::suite do repositório: é válida, as fixtures existem e a linha de base não passa por acaso` |
